常见 HTTP 状态：

| 状态码 | 说明                               |
| ------ | ---------------------------------- |
| `400`  | 请求参数错误                       |
| `401`  | API Key 缺失、无效、未激活或已过期 |
| `402`  | 余额不足或每日额度已用尽             |
| `403`  | 账户 API 功能或操作权限受限          |
| `404`  | 路径、模型或当前账户的任务不存在     |
| `409`  | 资源状态冲突，如用量尚待核对         |
| `413`  | 上传文件超过大小限制               |
| `429`  | 请求频率或并发超过限制             |
| `500`  | 服务内部错误                       |
| `502`  | 上游生成或结果交付异常              |
| `503`  | 上游、路由或限频服务暂时不可用       |
| `504`  | 等待上游或图片结果超时              |

错误示例：

```json
{
  "code": 401,
  "message": "API Key 无效",
  "error": {
    "type": "authentication_error",
    "details": "API Key 不存在"
  }
}
```

上例是图片/视频直接接口的错误结构。对话和图片兼容接口使用厂商风格的 `error` 对象，见[模型列表与错误格式](/conversation/models-and-errors)。并非每种错误都附带 `requestId`，日志应同时记录 HTTP 状态和响应正文。

## HTTP 失败与任务失败

查询接口返回 HTTP `200`，但 `status: "failed"` 时，任务已结束且生成失败，读取任务中的 `error.message` 与 `error.code`。HTTP `4xx/5xx` 则表示本次请求失败，已有任务仍可能继续执行。

图片兼容接口返回 `partial: true` 时，先保存已成功的 `data` 和所有 `task_ids`，再按 `errors[].index`、`task_id` 定位缺失结果。同步图片等待返回 `504` 时，可利用返回的 `task_ids` 查询 `/v1/images/{taskId}`；重发会生成新任务。

## 排查常见问题

| 现象 | 优先检查 | 处理方式 |
| --- | --- | --- |
| `401` 或 SDK AuthenticationError | 密钥完整性、有效期、多个认证头、站点归属 | 按[鉴权](/authentication)检查后再请求 |
| `404` 且返回 HTML | 请求实际 URL、`/api` 前缀、是否出现 `/v1/v1` | 使用工作台 Base URL；文档域名用于阅读 |
| 模型找不到、操作不支持 | 公开模型名、标准列表的 `supported_operations` | 切换到该模型声明的操作或查询可用模型 |
| `400` 参数错误 | 参数类型、公开名称、必填值、支持选项 | 从目录 `requestExample` 构建最小请求，逐项增加参数 |
| `402` | 余额和每日额度、用户级上限 | 查看工作台账单及 `/v1/account`；结合错误信息处理 |
| `413` | 单文件大小、请求体大小、代理上传限制 | 查询当前上传配置，压缩素材并检查代理限制 |
| `429` | 频率还是并发、总轮询量 | 按提示等待，减少并发并加入退避 |
| 上传 `400` | `file` 字段、实际 MIME 与文件内容 | 使用真实媒体文件；multipart boundary 由客户端生成 |
| SSE 一次性才显示 | 客户端缓冲、反向代理缓冲 | 用 `curl -N` 验证，并查看[代理配置](/conversation/reverse-proxy) |
| 生成请求超时 | 是否已经建立任务或收到响应 ID | 先查任务历史和已有 ID，再决定是否创建新任务 |
| 任务 completed 但缺少 URL | 结果字段、供应商返回及是否已交付 | 保存原始响应和任务 ID 联系支持，避免直接重发 |

图片、视频 JSON 请求的参考素材使用 HTTP(S) URL；本地文件先[上传](/files/upload)。OpenAI 图片兼容编辑接口另外支持图片 Data URL，详见其[协议说明](/images/openai-compatible)。

## 重试策略

查询等 GET 请求遇到网络故障、`429`、`502`、`503`、`504` 时，可在总时限内退避重试：先等 3 秒，再等 6、12、24 秒，加入少量随机等待；有 `Retry-After` 时优先参考它。批量轮询需结合每分钟限额，避免所有任务同时请求。

创建、对话生成和上传会产生新操作。遇到连接断开或超时，先核对是否已接受请求；本文示例只对查询自动重试。若 SDK 默认自动重试生成调用，可按业务需要设置 `max_retries=0`（Python）或 `maxRetries: 0`（JavaScript），由业务层统一判断。

参数错误、鉴权错误和余额问题需要先修复原因；连续原样重发只会重复产生同类错误。

## 保存诊断信息

记录请求时间、接口路径、模型、脱敏后的请求参数、任务或响应 ID、HTTP 状态、`requestId`、限频头和错误正文。文件记录大小、MIME 和文件 ID；流式调用记录终止事件及最终用量。提供这些信息能帮助定位问题。
